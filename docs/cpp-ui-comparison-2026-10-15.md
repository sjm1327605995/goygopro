## 对比条件与限制

- C++ 基准：`Fluorohydride/ygopro` 的 `gframe`（对照时使用的源码快照已从本仓库移除）。
- 当前程序：`bin/goygopro.exe`，通过 WebView2 CDP 操作真实 Wails 服务、真实卡库及「青眼一击.lua」引擎。
- WebView 内容视口分别设为 1024×640、1600×900；通过 DOM 边界、逐帧采样和截图检查当前表现。
- 未找到原版 C++ 可执行文件；`go version -m client.exe` 确认根目录 `client.exe` 也是 Go/Wails。工作区仅包含 C++ 源码，缺少完整构建入口、编译器和 Irrlicht 等依赖。
- 因此本报告是**C++ 源码规则与当前客户端实测对照**，不是原版程序与当前程序的截图差分。没有计算或宣称整屏像素相似率。

## 已确认的差异

| 优先级 | 项目 | C++ 源码行为 | 当前实测/实现 |
| --- | --- | --- | --- |
| P1 | 胜利与伤害播放顺序 | `duelclient.cpp:3192-3195` 先等待 30 帧，再递减 LP 10 帧并等待 11 帧，之后才能处理后续 MSG_WIN | 伤害浮字出现的第一条采样中，LP=500，`You Win!` 已同时出现；约 700ms 后数字才归零。胜利横幅的 2 秒持续时间正确，开始时机仍提前 |
| P2 | LP 数字、血条、伤害浮字 | `drawing.cpp:624-628` 每帧减去固定 lpd，数字与条共用 dInfo.lp；伤害红色、回复绿色、支付蓝色；浮字固定位置，后 10 帧降低透明度 | `PlayerPanel.tsx:30-56` 从事件到达起二次插值 700ms，血条直接读最终 LP；`LpFloatText.tsx:29-32` 显示约 1300ms。实测伤害颜色 `rgb(255,255,102)`，并有向上位移动画 |
| P2 | 左侧卡图的宽屏比例 | `game.cpp:2103-2104,2283-2291` 使用 ResizeCardImgWin，图像按 min(xScale,yScale) 等比缩放 | 当前整块 DesignSpace 沿 X/Y 分别拉伸。1600×900 下卡图 DOM 为 273.44×354.38，宽高比约 0.7716；源码卡图区域约 248×357，宽高比约 0.695。标准视口当前图像为 175×252，另有边框/内距差异 |
| P2 | 阶段/胜负横幅字号 | `game.cpp:1964` 在 OnResize 中重建 `48*yScale` 字号；900 高视口约 67px | `PhaseStrip.tsx:56` 的逆缩放抵消了整个 DesignSpace 缩放，实测横幅仍约 48px。上一轮将横幅字号固定的处理需要更正 |
| P2 | 普通弹窗的宽屏尺寸与位置 | `game.cpp:2029,2267-2274` 连接箭头窗为 ResizeWin(700,30,820,150)，120×120 固定尺寸，仅缩放中心位置 | 1600×900 下连接箭头窗实测 187.5×168.75，位置 (1093.75,42.19)；源码计算约 (1127,66)、120×120。录像保存窗已单独修正，实测仍为 310×120 |

## 本次确认与保留的正确项

- 真实单人残局能够完成攻击、选择攻击对象并最终将对方 LP 降到 0。
- 胜利与普通阶段采用 C++ 的英文横幅文案；胜利原因使用败者名称，未恢复全屏奖杯弹窗。
- 胜利横幅结束后才出现录像保存窗口；1600×900 下保存窗口仍是 310×120。
- 卡组主区、额外区、副区主要框架与 C++ DrawDeckBd 坐标有对应实现；双击不删除、右键删除、中键复制和指定位置拖放已有实际鼠标回归覆盖。本次未重新执行这 25 项历史回归。
- 本轮 DrawSpec 使用原版贴图和逐帧公式；此前像素断言验证的是绘制函数与源码参数，不足以证明整个客户端在所有分辨率下完全相同。
